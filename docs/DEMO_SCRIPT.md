# Demo Script

本脚本用于课堂汇报时按步骤展示知识管理 MIS Demo。推荐先执行 `docker compose up --build`，确认 seed data 已生成，再按下列路径演示。

## 1. 员工提交知识

账号：`employee@example.com / password123`

展示步骤：

1. 登录系统，观察左侧“知识工作台”菜单。
2. 进入“新建知识”。
3. 点击“知识模板”，选择“项目复盘模板”或“培训资料模板”，点击“插入模板”。
4. 填写标题、摘要、正文、分类、访问级别、标签。
5. 上传一个本地附件，展示附件元数据会进入知识条目。
6. 可先点击“保存草稿”，再进入“我的知识”查看草稿状态。
7. 回到编辑页，点击“提交审核”。

体现的 MIS 设计点：

- 知识采集子系统：表单采集结构化和非结构化知识。
- 输入设计：草稿允许不完整，提交审核时进行必填校验。
- 数据流程：前端表单通过 REST API 写入 MongoDB `knowledge` collection。
- 模板套用：第三轮补充的轻量模板用于展示“标准化知识采集”。

## 2. 部门知识管理员审核

账号：`manager@example.com / password123`

展示步骤：

1. 登录后进入“待审核”。
2. 找到刚才员工提交的知识。
3. 打开审核详情，查看标题、正文、元数据和附件。
4. 输入审核意见，点击“审核通过”。
5. 可另选一条待审核 seed 知识，输入意见后点击“驳回”，再切回 employee 的“我的知识”查看审核意见。

体现的 MIS 设计点：

- 知识分类与审核子系统：部门知识管理员负责本部门知识质量控制。
- 权限控制：manager 只能处理本部门待审核知识，system_admin 不负责知识审核。
- 业务流程：`pending -> approved/rejected` 状态流转写入 `reviews` 和 `statusHistory`。

## 3. 用户检索、阅读、评论和收藏

账号：`employee@example.com / password123`

展示步骤：

1. 进入“知识库”。
2. 用刚发布知识标题的一部分进行关键词检索。
3. 也可以进入“分类与标签管理”，点击“标签汇总”中的标签，跳转到知识库按标签筛选。
4. 打开知识详情页。
5. 展示标题、正文、分类、标签、版本、附件、审核记录和相似知识推荐。
6. 在评论区评分并提交反馈。
7. 点击收藏，再进入“我的收藏”确认收藏记录。

体现的 MIS 设计点：

- 知识检索与推荐子系统：关键词、分类、标签、排序与相似推荐。
- 知识共享与协作子系统：评价、评论、收藏沉淀用户反馈。
- 输出设计：详情页以文档阅读为中心，右侧展示结构化元数据。

## 4. 决策者查看统计 Dashboard

账号：`decision@example.com / password123`

展示步骤：

1. 登录后进入“统计分析”。
2. 展示知识总数、已发布数量、待审核数量、归档数量、总浏览量和平均评分。
3. 展示部门贡献排行、热门知识 Top 5、高频搜索词和状态分布。

体现的 MIS 设计点：

- 统计分析子系统：把业务行为数据转化为管理驾驶舱。
- 管理决策支持：通过贡献排行、热门知识和搜索词判断知识建设重点。
- MongoDB 聚合：后端 analytics API 基于 `knowledge`、`searchLogs` 等 collection 聚合。

## 5. 系统管理员展示系统管理

账号：`admin@example.com / password123`

展示步骤：

1. 进入“用户管理”。
2. 搜索用户，展示角色、部门、状态和操作。
3. 新增或编辑一个测试账号，说明 RBAC 角色如何影响导航和权限。
4. 查看“部门维护”区域。
5. 进入“系统设置”，展示系统状态、维护操作和备份模拟。

体现的 MIS 设计点：

- 用户与权限管理子系统：账号、部门和角色支撑 RBAC。
- 系统管理子系统：系统设置和备份模拟体现实施阶段的运维意识。
- 实施方案：Docker Compose 提供本地可复现运行环境。

## 老师追问时的回答建议

- 问：为什么没有 Elasticsearch？  
  答：课程 Demo 第一版使用 MongoDB text index 覆盖关键词检索；Elasticsearch 适合后续大规模知识库扩展。

- 问：标签为什么没有单独表？  
  答：当前采用 MongoDB 文档设计，标签作为 `knowledge.tags` 字符串数组嵌入知识文档；第三轮增加了标签汇总视图用于管理和检索入口。独立 Tag collection 是未来扩展。

- 问：附件为什么存在本地？  
  答：课程 Demo 使用 `server/uploads` 和 Docker volume 简化部署；生产环境可换成对象存储或独立文件服务器。

- 问：是否支持批量导入和实时协作？  
  答：本 Demo 优先保证核心闭环可演示，批量导入、多人实时协作和 WebSocket 属于后续 P2/P3 扩展。

- 问：如何证明系统稳定？  
  答：第二轮已补后端 API 集成测试，第三轮补前端 smoke 检查和展示前 release checklist。
